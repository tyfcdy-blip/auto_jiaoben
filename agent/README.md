# 原生执行器 v0.1 / v0.2 基础能力

使用项目 Python 3.12 虚拟环境运行 `python -m agent --config <本机配置文件>`；`--once` 只领取一次，供隔离环境验收使用。配置以 `config.example.json` 为参考，运行时别名必须指向本机真实的绝对可执行文件。节点令牌单独存放，不写入命令行、context、业务子进程环境或示例文件。

节点页面可填写电脑名称、运行环境及执行电脑上的程序绝对路径，并下载Windows一键接入包和一次性连接文件。执行电脑已有Python 3.12时，解压接入包并双击 `安装并连接.cmd`，选择连接文件即可自动导入、后台启动，并加入当前用户的开机启动；不再要求进入源码项目目录。原 `--import-connection` 和 `--config` 命令仍保留用于维护和其他操作系统。

导入默认写入当前用户的 `.automation-workbench/connections/<节点标识>/`，也可用 `--connection-dir <全新目录>` 指定；不覆盖已有目录。先验证运行时确实存在及远端 HTTPS，再限制新目录权限，分别落盘 `node-token.txt` 与不含令牌的 `agent.json`。Windows 使用当前身份 SID 设置独占 DACL，POSIX 使用目录 0700/文件 0600；失败时不保留半份连接文件。此权限保护不构成同用户业务子进程隔离，生产独立身份仍未开放。下载文件本身包含令牌，应在成功导入后删除，不提交仓库或发群。

`base_url` 可以包含控制台应用前缀，例如 `https://workbench.example.invalid/automation`。所有接口追加到此前缀下的 `/api/v1`；领取响应中的下载地址必须是同一前缀下的绝对路径，不接受绝对外部 URL、跳转、编码或目录穿越路径。明文 HTTP 仅允许本机测试地址。

当前只开放 `isolation=development`，仅执行 `side_effects=false` 的受信任程序。开发环境不是安全沙箱，同一系统用户可能读取进程可见文件；禁止装载真实业务密钥和不受信任代码。`os_user` 在本版明确拒绝，Linux/Windows 生产独立身份与 ACL 尚未验证，不允许借此执行正式上传。

一台电脑只运行一个执行器进程，同一个节点可以由工作台授权给多个项目。`slots` 是整台电脑共用的并发上限，不会为每个项目分别启动服务；运行中继续心跳及查询取消。命令行入口还会使用当前 Windows 用户下的全局进程锁，避免误启动多份执行器争抢同一个节点。包和输入经同源认证下载、容量及 SHA256 校验；ZIP 拒绝越界、链接、重复名称及特殊文件。业务入口由本机运行时别名启动，`shell=False`，参数通过 `--context-file` 传递。

目录型程序可在本机配置或连接文件加入可选 `input_roots`，值为最多 30 个绝对目录组成的列表，例如 `"input_roots": ["D:/AutomationInputs"]`。目录可以暂时离线，执行器仍能启动和心跳；实际任务访问该目录失败时才回报 `startup_failed`。省略时默认为空，拒绝目录任务。受管执行器会从工作台拉取带版本与摘要的电脑目录配置，原子写回本机配置并回报同步结果。配置了根目录后，心跳自动加入 `directory-input-v1`，计入最多 30 项能力；未配置根时不会通过手填同名能力冒充支持。

目录任务的领取响应新增 `input_directory`，同时必须有同值的 `parameters.input_dir`，且平台输入文件列表为空。执行器启动业务前验证所选目录在白名单内；根及祖先、内容均拒绝符号链接、Windows 重解析点、设备及硬链接。有界遍历最多 1000 个普通文件、1000 个目录（含所选目录）、深度 32，总字节数按 `max_expanded_bytes`（默认 100 MiB）。空目录、无权限、越界、超额或读中变动均回报既有 `startup_failed`，由平台监控产生告警。

目录输入不复制、不上传、不冻结。`context.input_manifest` 仍为 name/path/sha256；name 使用相对输入目录的 `/` 分隔路径，path 指向原文件绝对路径，`parameters.input_dir` 保留请求原值。生成摘要时检查前后元数据及目录增删；检查结束后文件仍可能变化，业务程序和上游需约定稳定交付，不能把此能力当作不可变快照。准备期间按已有周期心跳，但操作系统单次目录/文件读取阻塞无法由该白名单机制中断。与本次任务无关的离线根目录不会被访问，不会连带阻塞其他正常目录。Windows 网络共享建议使用 UNC 路径，并把访问凭据配置给实际运行执行器的 Windows 用户；工作台不保存共享账号或密码。当前仅验证可信开发程序，不是 OS 文件访问沙箱。

先落盘启动意图；Windows 先建立 Job Object，POSIX 先建立进程组，再解锁业务入口。Windows 超时/取消使用 Job 终止树，POSIX 使用进程组。重启发现意图、运行中或不可确认状态时只回报 unknown，绝不再次启动同一尝试。终态先持久化再发送，丢失响应时回传完全相同记录。

stdout/stderr 并发持续排空，有界内存队列和磁盘日志限额；截断及丢弃有明确系统记录。结果文件、进程退出与产物状态分别校验，不靠扫描 ERROR 判定业务失败。状态目录内的日志、包和输入不会自动到期删除；运维应使用已审查的保留策略，不可清理未交付或 unknown 运行。

Windows Job 限制不是账号安全隔离；节点失联/进程强停不代表外部写入已撤销。当前所有示例仅写入本次运行工作目录，不连接真实接口、钉钉或生产数据。
