# 钉钉机器人与脚本消息：极简接入

工作台把通知分成四处：**机器人连接**登记和启停群机器人；**通知规则**选择系统异常类型、任务成功消息及接收群；**消息记录**核对每次投递、重试或停用；**告警中心**处理异常本身。左侧先选择项目再配置；“所有项目”用于汇总查看记录。

1. 项目管理员到「机器人连接」新增获授权测试群的 Webhook 和可选签名密钥。连接初始停用，可直接点该连接的「发送测试消息」；平台向群发送一条固定文字并显示钉钉接口结果与测试编号。到群里核对同一编号后再启用连接。测试不受启停状态限制，每次点击都会实际发一条；超时或响应异常时送达情况未知，先核对群消息再重试。若钉钉拒绝，检查 Webhook、加签、关键词及机器人安全设置。脚本不持有凭据，也不自行选择群。请勿在聊天中传密钥。
2. 到「通知规则」按机器人选异常类型。新连接默认接收结果不确定、部分完成、定时计划错过/失败、执行/启动失败和执行电脑离线；持续排队默认不发送。旧连接尚无规则时沿用原先全部故障，保存一次后按选择过滤。恢复只发给收到原故障的连接。等级由平台依据异常事实确定，脚本不能设置。
3. 在「通知规则 → 任务成功消息」对目标任务启用并选**同项目**接收群。只有运行被确认成功且 `result.json` 的 `status=success`，平台才为该运行创建最多一条消息；失败由系统告警处理。规则在**运行完成时**读取，进行中的运行也按完成时配置决定。
4. 脚本按现有结果协议写入 `output/result.json`。`summary` 是运行摘要；若要向群发送专用文字，可额外写 `notification_text`（非空、最多 2000 字符）：

   ```json
   {
     "protocol_version": "1",
     "run_id": "来自本次运行上下文",
     "attempt_id": "来自本次运行上下文",
     "status": "success",
     "summary": "内部结果摘要",
     "notification_text": "今日已合并 3 份报表，结果已归档。"
   }
   ```

   没有 `notification_text` 的旧脚本沿用 `summary`。平台模板固定附上任务名和运行编号，然后放入这段文字；不会附加参数、日志、文件或完整 `metrics`。常见凭据形式会遮蔽，但脚本作者仍须避免个人信息、密钥和敏感明细。结果文件需按原协议写临时文件后原子替换；不能把上述示例编号当作实际值。
   **兼容顺序：**现有脚本使用 `summary` 无需修改。要新增 `notification_text` 的脚本，必须先把对应执行电脑的执行器更新到包含新结果协议的版本；旧执行器会拒绝它不认识的字段。平台服务和执行器更新完成后，再发布使用新字段的程序版本。
5. 在「消息记录」分别核对告警投递和任务消息，查看项目、连接、运行、内容、发送状态及尝试次数。发送失败会有限重试，不重跑业务脚本，也不会改变运行成功状态。外部已收到但响应丢失时可能重复送达，用运行/事件编号核对。连接停用后新消息记录为停用，不会在重新启用时补发。

验收应使用独立测试项目、合成任务和获授权测试群：先模拟失败确认告警类型与群消息，再运行带 `notification_text` 的成功脚本，核对只发一次、群内容和消息记录。真实 Webhook/加签、网络连通和群消息呈现必须单独核验；自动化 Mock 测试不等于真实送达。
