# 影刀或外部系统如何交付文件并触发

平台不接管影刀调度。影刀完成下载后，按下面顺序调用本工作台。业务程序只实现 context/result 协议，不负责钉钉。

## “创建接口”实际创建什么

工作台的任务触发、文件上传、状态查询和结果下载接口是统一且固定的，不为每个程序生成一套新的 URL。“事件接入 → 创建调用方”创建的是一组独立凭据，并把它限制到允许触发的任务；程序包定义的 `parameter_schema` 同时决定界面表单和外部 `parameters` 的校验规则。页面会列出每个任务的 task_id、参数名、类型、必填项和文件输入方式；部署实例的 `/api/docs` 提供可交互的 OpenAPI 接口文档。

外部参数到执行电脑的链路是：调用方把 JSON 放入 `parameters` → 工作台用本次参数覆盖任务的同名默认参数，未传字段继续使用任务默认值 → 按任务绑定的已发布程序版本校验合并结果 → 保存到运行记录 → 执行电脑领取任务时收到这份已解析的完整参数 → 执行器写入程序的运行上下文。调用方不能覆盖 command、version_id、node_id、credential 等受控字段。

## 先登记

在工作台创建项目、程序版本与任务。管理员创建专用调用方，只绑定允许触发的 task_ids；需要传文件时明确打开 allow_input_upload。该授权覆盖整个项目的批次，因此不应把互不信任的数据来源放在同一个项目。调用令牌只显示一次，保存在影刀凭据管理或受控秘密文件，不写脚本常量、参数、日志或群消息。

接口前缀是控制台地址加 `/api/v1`；部署在 `/automation` 时完整前缀包含 `/automation/api/v1`。全部业务请求使用 `Authorization: Bearer <调用方令牌>`，远端必须通过HTTPS。以下都是字段示意，不是真实账号或生产参数。

## 文件夹直接输入

如果影刀已把文件下载到执行电脑可访问的文件夹，可以直接传目录，不需要再上传文件。先将程序输入方式设为“文件夹”，任务固定到已配置允许读取目录的执行电脑。专用调用方只需任务触发权限，无需打开文件上传权限。

在全部下载完成、文件关闭后，调用 `POST /tasks/{task_id}/runs`：

```json
{
  "event_id": "download-2026-09-17-001",
  "parameters": {
    "input_dir": "D:\\业务下载\\2026-09-17-001",
    "batch_key": "2026-09-17-001"
  }
}
```

示例路径需要换成实际执行电脑可访问且已获准读取的目录；其他业务参数放在同一 parameters 中。不能同时传 input_batch_id。网络重试沿用同一 event_id、batch_key 和参数；每次新的业务交付使用新的批次编号。受理后用 run_id 查询最终状态。当前没有整任务自动重试，失败后需先核对原因和处理结果；不能用新批次编号绕过未知状态核对。

平台在执行电脑上检查目录范围、可读性、文件和容量，直接提供原文件清单；不上传、不复制，也不冻结原目录。处理期间上游不得继续写入同一批文件。定时计划同样支持 input_dir 和 batch_key，批次编号可以使用完整的 `${scheduled_date}` 或 `${previous_month}`；目前不能拼接日期目录，每天多次不同交付也不能共用同一个日期批次编号。详见[目录输入配置](folder-input-guide.md)。

## 上传文件批次与运行

1. 为一份确定的业务输入选择稳定 label，如 `2026-08`。调用 `POST /batches`，内容 `{"project_id":"已登记项目ID","label":"2026-08"}`。label在项目内唯一。若超时重试返回409，分页查询 `GET /batches?project_id=...` 找到完全相同的标签，不新建随机标签绕过去重。
2. 对每个文件调用 `PUT /batches/{id}/files/{文件名}`，请求体为文件原始字节，不是本地路径。文件名不能带目录。重发同名同内容返回原文件记录；同名不同内容拒绝，修订必须另建明确的新标签。
3. 调用 `GET /batches/{id}`，核对全部预期文件的名称、大小、SHA256；文件全部下载关闭并校验后再 `POST /batches/{id}/ready`。这一步表示上游承诺本批次已齐全，平台不会猜测还缺多少张表。
4. 调用 `POST /tasks/{task_id}/runs`，例如 `{"event_id":"download-2026-08-r1","input_batch_id":"已冻结批次ID","parameters":{"period":"2026-08"}}`。首次202只是持久受理，重复相同事件返回200和原run_id；同event_id不同内容返回409。
5. 用 `GET /runs/{run_id}` 查询最终状态。queued/waiting_input/running均不是成功，unknown需要核对；succeeded也只代表登记的operation成功。nine的preflight成功不等于上传成功。

网络超时后保持原event_id及原参数重试，采用调用方的有限退避；429保留事件稍后重试，401/403停下修复授权，409核对冲突，422修正输入。不要换event_id或新批次强制把未知上传再执行一次。平台不要求上游无限等待HTTP连接。

工作台按环境配置限制单文件、单批次文件数与容量、项目输入总容量和待交付批次数，超限返回 413。人员账号可以删除未上传任何文件且未被引用的空批次；外部调用方不能删除批次，避免一个上游删除另一个上游的数据。已上传或已就绪数据的正式归档与保留周期仍应由运维策略统一确定。

## 影刀取得 JSON 结果和文件

影刀的接入是三个 HTTP 步骤，不要求影刀安装工作台执行器：

1. 下载结束后调用前述 `POST /tasks/{task_id}/runs`，保存响应中的 `run_id`。`202` 是首次受理，`200` 且 `deduplicated: true` 是同一 `event_id` 的重试，两者都**不是执行成功**。调用方令牌须在工作台“事件接入”创建并仅授权所需任务。
2. 以同一令牌调用 `GET /runs/{run_id}`，直至 `state` 离开 `waiting_input`、`queued`、`leased`、`running`、`cancel_requested`。成功时 `result` 是业务程序按 `result.json` 协议写入的原始 JSON；`artifacts` 是工作台已归档的文件清单，包含 `id`、`name`、`size`、`sha256`。`failed`、`partial`、`unknown`、`canceled` 都不能当成成功；特别是 `unknown` 需要人工核对外部副作用。
3. 只在确认业务状态及 `artifact_state` 后，对每个文件调用 `GET /runs/{run_id}/artifacts/{artifact_id}`。响应是原始字节，不是 JSON；按清单中的文件名保存，并校验大小和 SHA256。调用方只能查询和下载自己曾触发的运行；其他调用方即使授权同一任务也不能读取其结果。令牌撤销后下载失效。运行详情与文件下载均接受已授权的人员账号。

`result` 可能是 `null`（未要求结果报告的旧程序），`artifacts` 可能为空；需要结构化返回时应在程序版本启用必需结果报告，并按[脚本接入规范](../脚本与程序开发接入规范.md)写 `result.json`。工作台不会把异步长任务压在影刀的一个 HTTP 请求里等待，也不会把脚本报错包装为成功的 HTTP 200。网络超时后用原 `event_id` 和原参数重试触发；查询超时直接用已保存的 `run_id` 再查。影刀当前版本的具体 HTTP 指令界面需在实际客户端验收。

## 钉钉中的结果入口

任务启用“成功结果通知”并绑定已启用的机器人后，脚本成功且结果报告的 `status` 为 `success` 才会生成通知记录。`notification_text` 存在时用于群消息正文，否则使用 `summary`。如在部署环境配置 `WB_PUBLIC_BASE_URL=https://工作台域名`，群消息还会附加 `/#/runs/{run_id}` 的查看入口；使用子路径时由 `WB_BASE_PATH` 自动拼接。该入口要求人员登录并有项目权限，文件仍走工作台的鉴权下载接口。开发机的 `127.0.0.1` 链接无法供别的电脑或手机访问；上线前需有可访问的 HTTPS 地址。

当前自定义机器人通道发送文本，不向钉钉上传文件本体。旧通知保留创建时选定的机器人连接，事后切换任务配置不会自动重发到新机器人。连通性测试成功也不会生成任务通知，须观察新运行的“消息记录”。真实影刀指令配置、移动端链接可达性和真实群送达需在对应环境验收。

## 与定时并存

定时任务同样带parameters，并可设置 `input_label: "${previous_month}"`。这两个日期模板目前只支持完整字符串 `${previous_month}` 和 `${scheduled_date}`，不支持拼接。任务会等待对应标签的冻结批次；同一程序/operation/业务键和批次的事件、计划合并为同一运行。参数或版本冲突会明确拒绝，不能悄悄覆盖先前受理。

需要固定输入的计划可使用 input_batch_id，不能同时设置input_label。新计划默认暂停；实际启用前确认任务operation、参数、输入和执行节点。

机器接口定义见 [OpenAPI](../contracts/openapi.json)，当前限制见 [实施契约](implementation-contract.md)。本说明对应开发版本，尚无真实影刀或正式上传验收证据。
