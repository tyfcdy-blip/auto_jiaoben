# 文件夹输入与合成脚本测试计划

2026-09-17。用户已同意当前电脑进行首轮测试，使用自动生成的独立目录和脚本，不使用真实业务文件。

执行模式：全过程开发。此切片按L3路径访问与跨模块执行处理；授权范围为目录输入功能、自建程序、本机隔离测试。无生产部署、真实业务写入、真实钉钉发送或存量数据库结构变更。Git main未提交，全部原未跟踪源码作为基线保留，不提交。

## 最短实现路径

复用已存储的版本JSON Schema：使用 `x-workbench-input: "directory"` 注解标记目录输入，声明input_dir和batch_key。后端根据版本推导任务input_mode，不新增数据库列；原上传批次协议与普通任务保持兼容。目录任务必须固定执行节点，通过同一带参事件/计划受理并按batch_key去重。

执行器新增可选input_roots白名单，默认关闭目录读取；有配置才报告directory-input-v1能力。平台只派发目录任务给该能力的节点，claim只在目录模式增加input_directory。执行器在业务启动前核验根目录/目标目录、文件数量与总量、普通文件、路径与链接、可读性，生成原协议input_manifest，直接读取原目录，不复制或上传，不宣称冻结快照。输入下载完成且处理期间不再改写由上游保证。

## 配置与外部边界

本轮使用当前电脑、隔离目录、已有Python/Node环境、本地Docker开发实例；根目录只授权本轮生成的测试目录。后续用户只需提供执行电脑、可访问的输入根目录、运行环境路径、计划时间/业务参数；接真实影刀时配置专用调用凭据。真实钉钉测试还需授权测试群及连接配置，秘密不放聊天或示例代码。

共享目录必须由运行执行器的系统身份可访问，优先UNC而非交互用户映射盘。本轮不能验证另一台电脑的账号、网络和共享权限，也不把本机成功作为共享目录验收。

## 验证与退出

分工作包执行实际测试、类型/构建、静态检查；合成集成使用稳定可识别名称、独立项目与目录，禁止执行原nine真实上传。失败先修复并复验，不跳过关键测试。最终记录通过/失败/跳过数、退出码、独立审查和剩余生产事项。保留旧config/普通claim；回退无需数据库逆迁移，新目录任务在旧执行器上不可调度。
