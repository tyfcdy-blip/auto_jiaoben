# 钉钉连接测试：实施与用例计划

基线：`main` 尚无首次提交；本工作包只触及机器人连接页面、通知发送器、连接 API、测试和接入说明。模式：全过程开发；等级：L3（向外部钉钉接口发消息并涉及项目权限）。不更改数据库结构、告警投递规则或脚本结果协议。

| 编号 | 场景与输入 | 预期及验证层级 |
| --- | --- | --- |
| CP-01 | 项目管理员测试未启用的已登记连接；模拟钉钉 HTTP 200 / `errcode=0` | 仅发送一条固定内容，加签正确；即时返回成功、测试编号；API + UI |
| CP-02 | 钉钉返回非零码、非 JSON、HTTP 错误、连接超时 | 即时失败，提示已知失败或送达未知；不泄露 Webhook、签名和原始响应；单元 + API + UI |
| CP-03 | 未登录、只读成员、其他项目成员、不存在连接 | 无外发请求；401/403/404；API |
| CP-04 | 用户连续点击、连接页所有项目视图 | 提交期间不能重复点击，按项目切换清理反馈；组件 |
| CP-05 | 测试操作审计、异常不改原投递记录及连接启停状态 | 请求和结果有审计；原运行/告警通知流程回归；API + 回归 |

测试使用隔离 SQLite、合成钉钉 Webhook 和 `httpx.MockTransport`，不向真实群发消息。最后执行相关后端用例、前端组件测试、静态检查、构建、通知模块回归；真实群送达由项目管理员在获授权测试群手动点一次并核对群消息，自动化测试不能代替该项。
