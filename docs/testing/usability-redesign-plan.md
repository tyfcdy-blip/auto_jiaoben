# 接入简化与界面改版：实施及验证计划

## 目标与边界

用户要求：判断生产状态，按必要功能简化程序版本、执行电脑、输入文件接入，并改造为现代浅色毛玻璃界面。当前仍为开发验证环境；不以视觉完成替代生产验收。

执行模式：全过程开发。整体按 L2 跨前端/Agent 接入处理；涉及凭据文件的部分执行权限及故障专项验证，不改变后端授权、数据库结构、业务去重、调度并发、外部写入门禁。Git 为 main 未提交仓库，已有全部未跟踪文件视为基线，不提交或清理。

必要条件：程序内容可追溯、电脑有独立身份且心跳真实、文件齐套后才允许执行、任务保留参数/定时/事件、故障可定位。界面应自动完成组织步骤，不能删去上述保证。

## 设计系统

明亮、可信、轻盈的日常工作工具。导航和顶栏采用浅色透明毛玻璃；数据表格使用高对比的实色内容区。主蓝 #2563eb，薄荷 #0f9d8a，暖橙 #d88435；8px 间距节奏，16px 面板圆角。中文优先，避免大段英文装饰和无意义统计；使用真实运行和在线状态。支持窄屏及减少动态效果偏好。

## 验证规则

仅用本地隔离项目、合成程序和文件，不连接真实外部业务，不发送钉钉消息。不更换用户当前预览数据库；前端构建可更新原地址静态资源。后端或 Agent 变化先在隔离测试验证。

执行：frontend 的 Vitest、TypeScript/Vite 构建、Prettier，Python pytest/Ruff，真实浏览器 smoke 和新增接入用例。功能测试可模拟网络失败，核心运行链路使用实际 API/PostgreSQL/Agent。图片必须实际浏览器渲染后检查。测试结果在实施完成后记录，不提前填写通过。

退出：相关构建和关键用例通过，无未关闭 P0/P1；独立复核与未验证生产项明确披露。此次改版不授权生产部署，不改变真实凭据或已有业务文件。
