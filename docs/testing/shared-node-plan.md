# 共享执行电脑与目录授权改造计划

## 目标与边界

把执行电脑从“项目内节点”提升为可被多个项目授权使用的物理执行资源。一台电脑保持一个节点身份和一个Agent进程；电脑并发额度全局生效。电脑级目录是本机允许范围，项目级目录必须是其子集。

本里程碑不宣称目录白名单是操作系统沙箱。业务程序仍以Agent的Windows身份运行，生产隔离依赖专用低权限账号、共享权限和NTFS ACL。本次不自动合并已有的多个节点，不修改历史运行的node_id，不操作生产数据库。

## 兼容数据模型

- 保留 `nodes.project_id` 作为旧节点的归属项目，避免破坏历史任务、运行和告警外键。
- 新增 `node_project_grants`，保存节点与项目的多对多授权、项目目录子集、启停状态和最近领取时间。
- 新增 `node_config_state`，保存期望目录、配置修订号、Agent确认状态、错误和最近报告的目录状态。
- 初始化时为每个旧节点回填原项目授权；旧目录只存在Agent本机，必须由新版Agent报告后才能纳入受管配置，不推断为全盘授权。

## 工作包与验收

| 工作包 | 实现 | 关键验收 |
| --- | --- | --- |
| W1 数据与兼容初始化 | 新表、幂等回填、旧字段保留 | 旧节点ID/任务/运行不变；重复初始化无重复授权 |
| W2 权限与维护API | 节点详情、电脑级目录更新、项目授权增改 | 仅平台管理员扩大电脑权限；项目目录必须为电脑目录子集；并发修订冲突返回409 |
| W3 调度与撤权 | 按授权表跨项目领取、全局slots、轮转项目、开始前复核 | 两项目共享一个节点；无授权不领取；撤权后不能启动；总并发不超节点slots |
| W4 Agent配置同步 | 拉取配置、原子保存、确认修订、共享目录状态 | 未确认配置不领取；失败保留旧配置；共享目录离线不阻止Agent启动 |
| W5 前端维护 | 编辑电脑、目录、项目授权、同步状态 | 已登记电脑可继续维护；明确待同步/已生效/失败；不暴露其他项目信息 |
| W6 安装与单实例 | 标准安装复用节点身份，当前用户只运行一个Agent | 重复启动被本机锁拒绝；多项目不增加后台Agent数量 |
| W7 回归与发布门禁 | Python、API、Agent、前端、Docker与独立复核 | 无P0/P1；迁移、回滚、共享目录人工步骤完整记录 |

## 测试矩阵

- 正常：节点授权给两个项目，分别执行普通任务与目录任务。
- 权限：项目A不能查看或使用项目B目录；项目管理员不能扩大电脑级白名单。
- 边界：Windows盘符、UNC、大小写、相邻前缀、重复根目录、空目录授权、最多30项。
- 配置：修订冲突、Agent离线、应用失败、重复确认、旧Agent、配置回退。
- 调度：全局slots、项目轮转、公平领取、固定节点、撤权与领取并发、维护状态。
- 故障：共享目录暂时不可达、Agent重启、工作台重启、重复Agent启动。
- 兼容：旧节点回填、历史任务与运行可查、旧连接文件仍能导入。

## 发布与回滚边界

代码和迁移先在隔离数据库验证。更新真实本地环境前备份数据库与Agent配置，暂停派发并等待在途运行结束。配置回退通过发布新修订完成；软件回退必须同时恢复匹配的数据库和程序快照。已有多个旧节点只能在人工确认无在途或未知运行后合并，本次不自动处理。
