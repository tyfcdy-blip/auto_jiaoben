# 复用服务器 PostgreSQL 17 实施与测试计划

日期：2026-11-16。模式：全过程开发。等级：L3；涉及共享数据库实例、凭据、Docker网络、初始化顺序、备份恢复及两个项目的共同故障域。

## 已知事实与边界

- 服务器已有 PostgreSQL 17，容器为 `muyaju-data-reservoir-db-1`，持久卷为 `muyaju-data-reservoir-pg17`，仅通过Docker网络访问5432，不映射宿主端口。
- 工作台使用独立数据库、独立用户和独立密码，只在自己的数据库建表；数据库主机名和共享Docker网络名由服务器管理员提供，不能写死容器IP。
- 本轮只修改本地源码、部署配置和合成测试，不连接服务器、不读取现有数据库凭据、不创建数据库或账号。
- 工作台现有 `deploy/operations.py` 的数据库备份恢复绑定自带 `db` 服务，不能用于共享实例；共享实例的项目级备份恢复必须由服务器管理员执行并验收。

## 安全与停止条件

外部网络名和数据库主机名必须由管理员提供；应用只获得自己数据库权限。连接文件、实际env和密码不得提交Git。共享实例资源、备份窗口、重启影响、连接上限和磁盘告警未确认前，不允许正式部署。初始化检测到既有不兼容表结构时保持拒绝，不自动迁移或覆盖。

退出条件：EP01–EP09适用项通过，无未关闭P0/P1；真实服务器网络、权限、备份恢复和共同故障影响未执行时标记未验证。回退部署配置不会删除共享数据库；数据库回退只能由管理员用该项目的独立备份执行。
