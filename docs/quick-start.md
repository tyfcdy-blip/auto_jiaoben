# 工作台极简使用说明

这份说明只回答三件事：怎么先试一下、怎么接入一个真实脚本、以后每天怎么用。文件夹输入场景指“影刀先把文件下载到某个文件夹，再让工作台调用脚本处理”。

## 一、现在立刻试跑

1. 打开 `http://127.0.0.1:18080`，账号是 `admin`，密码使用本机 Docker 管理员密码。密码不写入说明书和代码仓库。
2. 左上角选择项目 **文件夹输入验收-9f7faf5e**。
3. 进入“任务管理”，找到 **Python CSV 合并**，点击“立即运行”。
4. 输入文件夹已经填好；把“批次编号”改成一个从未使用过的值，例如 `manual-20260917-01`，点击“确认运行”。
5. 进入“运行中心”查看状态、日志和结果。成功后可下载 `merged.csv`。

当前项目还有三个测试任务：Node.js目录统计应成功；Python主动失败和Python等待/取消是故障测试，显示失败或超时属于预期。测试电脑当前在线；如果电脑或执行器重启，按本文“执行电脑掉线”处理。

## 二、接入一个真实脚本：只做一次

按下面顺序配置：**执行电脑 → 程序 → 任务 → 触发方式**。

### 1. 连接执行电脑

进入“执行电脑”，点击接入电脑，填写：

- 电脑名称：容易识别的名称，例如“财务处理电脑”。
- 运行环境：Python或Node.js。
- 程序路径：这台电脑上的完整路径，例如 `C:\Python312\python.exe`，使用虚拟环境时填虚拟环境里的 `python.exe`。
- 允许读取的文件夹根目录：一行一个，例如 `D:\影刀下载`。脚本只能读取这些根目录及其子目录。

点击“登记并生成连接文件”后，分别下载“一键接入包”和“连接文件”。在执行电脑上解压接入包，双击 `安装并连接.cmd`，选择连接文件并核对页面显示的工作台地址、运行环境和读取目录；工具会自动导入、后台启动，并加入当前Windows用户的开机启动。完成后回到页面刷新，确认电脑显示在线。连接文件没有防篡改签名，必须直接来自可信工作台；导入后删除，不要转发、编辑、发到群聊或提交到Git。

同一台电脑只登记一次、只运行一个后台执行器。平台管理员先让电脑“进入维护”，再点“配置电脑与项目”，即可把这台电脑授权给多个项目，并为每个项目分别填写可读子目录。跨项目共享电脑首版固定一次运行一个任务，避免两个项目同时操作同一物理目录；保存后等待“配置同步”显示“已同步”，再结束维护。以后新增项目或目录不需要重新下载连接文件，也不需要再安装一个执行器。

首版仍要求执行电脑已有Python 3.12。若启动接入工具的Python已经具备执行器依赖，接入工具直接复用；否则会创建独立环境并联网安装固定版本依赖。无需进入源码项目目录。

### 2. 登记程序

把脚本入口和所需代码打成ZIP，不包含密码、虚拟环境、缓存和业务文件。进入“程序管理”，点击接入程序，填写：

- 程序名称。
- 输入方式选择“执行电脑上的文件夹”。
- 运行环境选择Python或Node.js。
- 入口文件填写ZIP内相对路径，例如 `main.py` 或 `scripts/main.py`。
- 选择ZIP，并勾选“校验通过后发布”。

点击“上传并发布”。脚本仍需遵循工作台上下文和结果协议；钉钉告警由工作台负责，脚本不发送告警。

### 3. 创建任务

进入“任务管理”，点击“创建任务”，填写：

- 任务名称和刚发布的程序。
- 固定执行电脑。目录任务不会选择未配置读取根目录的电脑。
- 输入文件夹：实际执行电脑可以访问的完整路径，例如 `D:\影刀下载\待处理`。
- 批次编号：创建时先填一个默认示例值；每次实际运行都可以修改。

其他业务参数、最长运行时间和互斥资源放在“高级设置”中。创建后先手动运行一次，确认日志、结果和产物正确，再配置自动触发。

## 三、日常运行

影刀每次下载建议使用独立子目录。文件全部下载完成并关闭后再触发；脚本运行期间不要继续改动这个目录。

手动运行只需：

1. “任务管理”点击“立即运行”。
2. 填本次输入文件夹。
3. 填本次唯一的批次编号，例如影刀流程编号或 `20260917-订单001`。
4. 确认运行，在“运行中心”查看结果。

同一批文件因网络问题重试时，保持原批次编号和参数。新的文件交付使用新的批次编号。不要为了绕过失败或未知状态随意换编号。

## 四、自动触发

### 定时运行

进入“任务管理”，在对应任务上点击“定时运行”→“添加定时计划”，选择每天、每周、每月或 Cron 时间，填写该计划的运行参数。文件夹任务可以使用完整的 `${scheduled_date}` 作为批次编号，表示计划日期；保存后计划默认关闭，核对无误再点击“启用”。

“定时计划”页签集中显示当前项目的计划、下次触发时间、启停状态和最近调度异常。点击计划右侧的“运行记录”，可以只查看该计划实际触发的运行。重要任务建议选择“错过时补最近一次”；“错过时跳过”会在调度器超过一分钟未受理时顺延，并在计划和告警中心留下原因，由平台按已配置的钉钉连接发送通知。

任务和定时计划都可以编辑、启停和删除。任务已有运行历史时不能物理删除，只能停用，以免破坏运行审计；刚建错且没有运行、计划或调用方引用的任务可以删除。删除定时计划不会删除它已经产生或关联的运行记录。

目录任务的定时计划默认使用 `${scheduled_date}` 作为批次编号。同一业务批次编号用于幂等去重：固定编号此前已经运行过且参数与程序版本相同时，计划到点后会关联已有运行；其他参数不同则报告业务批次冲突，均不会再次启动程序。计划页会明确显示关联结果。每天处理一批文件时保留 `${scheduled_date}`，同一天需要多次独立处理时应由事件触发传入不同批次编号。

定时运行适合固定目录且每个周期只处理一次的任务。若同一天需要处理多个独立批次，不能全部只用 `${scheduled_date}`，应改用影刀事件触发并传各自批次编号。

### 影刀完成后触发

进入“调用方管理”，创建调用方，只勾选允许触发的任务。目录输入不需要开启“文件上传权限”。创建后凭据只显示一次，应保存在影刀的凭据管理中。

影刀最后一步调用：

```text
POST http://工作台地址/api/v1/tasks/{任务编号}/runs
Authorization: Bearer <调用方凭据>
Content-Type: application/json

{
  "event_id": "本次影刀流程的唯一编号",
  "parameters": {
    "input_dir": "D:\\影刀下载\\本次目录",
    "batch_key": "本次业务批次编号"
  }
}
```

返回HTTP 202表示已受理，不表示脚本已经成功。保存返回的 `run_id`，随后查询 `GET /api/v1/runs/{run_id}`，或在“运行中心”查看最终状态。网络超时重试时，event_id、batch_key和其他参数必须保持不变。

## 五、出错时先看哪里

| 现象 | 先检查 |
| --- | --- |
| 执行电脑离线 | 执行电脑是否开机、执行器窗口是否还在运行、工作台地址是否可达 |
| 目录被拒绝 | 路径是否为完整绝对路径、是否位于允许读取的根目录下、目录是否为空 |
| 一直排队 | 固定电脑是否在线、运行环境是否匹配、该电脑是否已有任务在运行 |
| 程序失败或超时 | 在运行详情查看系统日志、stdout/stderr、退出码和结构化结果 |
| 重复请求没有新运行 | 同一event_id或业务批次会去重；先打开原运行记录核对 |
| 没有钉钉消息 | 先确认工作台是否已生成告警，再检查项目的钉钉通道；当前测试项目没有发送真实钉钉 |

## 六、Windows 共享文件夹

跨电脑目录优先填写 UNC 路径，例如 `\\fileserver\finance\pdd`，不要依赖 `Z:` 这类映射盘符。映射盘符通常只属于交互登录会话，后台启动时可能看不到。

1. 在执行电脑上，用运行执行器的同一个 Windows 账号打开该 UNC 路径并完成登录。
2. 如需长期保存凭据，使用 Windows“凭据管理器”保存文件服务器凭据；不要把账号密码填入工作台、脚本参数或连接文件。
3. 在“执行电脑”中进入维护，把共享根目录加入“电脑允许读取的根目录”。
4. 在对应项目行只填写它需要的子目录，保存并等待配置同步。
5. 结束维护，先用无敏感数据的小目录手动运行一次。

共享服务器暂时离线不会让执行器整体离线，也不会影响这台电脑上的其他正常根目录；使用该共享路径的任务会启动失败并由工作台生成告警。在线状态表示执行器与工作台心跳正常，不代表每个共享目录都始终可访问。

当前旧测试执行器仍可用下面命令重启；使用一键接入包登记的新电脑不再需要手工运行：

```powershell
.venv/Scripts/python.exe -m agent --config runtime/folder-acceptance/docker-01/connection/agent.json
```

## 上线前还要完成

当前版本可以做本机合成测试和可信脚本联调，尚不能直接判定生产可用。正式使用前还需把执行器安装为受限系统账号下的常驻服务，并完成真实影刀、共享目录权限、钉钉测试群、服务器HTTPS、备份恢复和业务系统写入验收。
