## 5. 首次部署步骤

所有命令在服务器受控部署目录执行；实际文件名、项目名和镜像摘要以本部署单为准。

1. 拉取并核对源码tag或仅取得经过批准的部署文件；服务器不临时改代码。
2. 复制 `deploy/.env.production.example` 为不纳入Git的实际环境文件，填完全部占位项。
3. 用 `deploy/bootstrap.py --directory <生产秘密绝对目录>` 在服务器生成一次秘密；发现已有目录立即停止，不能覆盖。
4. 以 `WB_DISPATCH_ENABLED=false` 解析配置：

   ```bash
   docker compose --env-file deploy/.env.production -f deploy/compose.yaml config --quiet
   ```

5. 拉取固定RepoDigest，检查镜像标签：

   ```bash
   docker pull <完整RepoDigest>
   docker image inspect <完整RepoDigest> --format '{{json .Config.Labels}}'
   ```

6. 只启动数据库并等待健康，然后运行一次 `init-db`：

   ```bash
   docker compose --env-file deploy/.env.production -f deploy/compose.yaml up -d db
   docker compose --env-file deploy/.env.production -f deploy/compose.yaml run --rm init-db
   ```

7. 启动API和Worker，保持派发关闭：

   ```bash
   docker compose --env-file deploy/.env.production -f deploy/compose.yaml up -d --no-build api worker
   docker compose --env-file deploy/.env.production -f deploy/compose.yaml ps
   ```

8. 首次且仅首次运行 `init-admin`。管理员从受控秘密文件取得初始密码，首次登录后按组织规则保管；不要粘贴到部署记录。
9. 配置HTTPS代理并验证页面、登录、API文档、文件上传下载、子路径、请求大小和安全响应头。
10. 先保持无计划、无调用方、无在线Agent，完成只读健康和备份基线。

## 6. 试点启用与验收

1. 创建普通管理账号和项目角色，验证管理员、开发者、操作员、查看者的权限边界。
2. 连接一台试点执行电脑；核对Agent只需出站HTTPS，目录白名单和Windows账号权限符合预期。
3. 配置钉钉测试群，发送连接测试；再用合成失败任务验证异常告警和消息记录。
4. 上传已验证的Python/Node无副作用程序，分别验证参数、拖拽文件、目录输入、JSON结果和文件产物。
5. 验证手动、定时和影刀/API事件触发；网络重试必须复用原事件ID。
6. 验证执行电脑离线、程序失败、超时、取消、Worker重启和服务器重启后的状态。
7. 完成一次一致性备份，并在隔离实例执行恢复演练；恢复实例保持派发关闭。
8. 连续观察期和通过标准由业务负责人填写。完成正式启用决定后才把 `WB_DISPATCH_ENABLED` 改为 `true` 并滚动更新API/Worker。

## 7. 发布后观察

记录API/Worker/数据库健康、磁盘增长、待处理通知、离线电脑、排队任务、失败率、备份状态和证书期限。当前Worker没有HTTP健康端点，必须使用组件水位和独立监控，不以容器“正在运行”代替调度正常。

## 8. 回退和停止条件

出现下列情况立即关闭派发并保留证据：登录或越权P0/P1、数据库/文件不一致、任务重复执行、跨项目数据暴露、密钥泄露、调度状态无法确认、恢复失败、钉钉持续异常或磁盘逼近保留阈值。

应用回退顺序：关闭派发 → 核对在途/unknown任务 → 停止API和Worker → 保存日志与执行器状态 → 按一致性恢复点决定“仅换镜像”或“数据库与平台文件同时恢复”。数据库结构变化后不得只换旧镜像。恢复实例不得与原实例同时派发任务。

镜像回退只允许使用部署单记录的上一RepoDigest或校验通过的离线镜像包。外部系统已经发生的写入不随镜像或数据库回退撤销，必须按业务补偿方案处理。
