# 从可运行走向可用：接入简化与生产边界

2026-09-17。当前是可联调的开发版本，尚未达到生产可用状态。此次实际修改交互和执行器接入，不重建调度系统、不变更数据库结构。

## 日常操作应当多简单

| 用户要做的事 | 现在的操作 | 系统保留的必要保证 |
| --- | --- | --- |
| 接入程序 | 在程序库选 ZIP，填名称、环境、入口，一次上传；版本名自动生成 | 入口及 ZIP 校验、权限校验、不可变发布版本、审计 |
| 更新程序 | 在原程序下点更新，上传新包 | 历史版本保留，已有任务继续绑定原版本，不自动替换正在运行的代码 |
| 连接电脑 | 填电脑名称和运行环境路径，下载连接文件，在电脑上导入并启动 | 独立节点凭据、文件访问权限、真实心跳；登记不冒充在线 |
| 提交业务文件 | 起名称、多选本次全部文件、一次提交 | 每个文件上传成功后才确认齐套；部分失败保留进度，重试使用同一批次 |
| 创建任务 | 选程序和执行电脑；默认选择可用已发布版本 | 参数、互斥、超时、业务去重仍可在高级设置配置；后台鉴权不变 |
| 看是否完成 | 进入运行中心查看状态、结果、日志和产物 | 进程退出、业务结果及不确定状态继续分别记录 |

程序包仍须由开发者按现有接入规范准备。上传不会自动把任意旧脚本改造成合规程序，也不会安装第三方依赖。运行环境应在执行电脑上准备好；不同 Python 虚拟环境、Node.js 或其他语言可以通过运行时别名区分。不是每次运行都重复登记版本和电脑。

外部写入程序可以先存为草稿，但当前开发门禁不允许发布执行。开发者上传后由项目管理员发布；项目管理员接入普通程序时可一次完成上传和发布。

事件触发仍由上游系统调用接口交付文件和触发任务，日常不要求人工再到文件页上传一次。文件页用于人工交付、检查和恢复。定时与事件仍支持业务入参，钉钉消息仍由工作台承担。

极少数创建请求若发生响应丢失或响应损坏，界面会停止重复创建，并提示从列表核对。不能用“再点一下创建”猜测服务端是否已经保存；已取得对象编号的上传、发布步骤则可以继续。

## 这轮界面

使用 web-design-engineer 技能，保持现有 Vue 技术栈，无新增前端依赖。浅色毛玻璃侧栏与顶栏、蓝色主操作、薄荷和暖橙辅助色；数据表格保持高对比。导航分日常工作和管理设置，首页突出接入程序、创建任务、查看运行。手机任务表直接保留操作按钮。

本地预览仍为 http://127.0.0.1:6465，原账号和数据库未替换，刷新会按现有规则重新登录。Docker 开发实例为 http://127.0.0.1:18080，本轮已更新 API/worker 镜像并完成真实浏览器验证；与本地预览是两个独立测试实例。

## 最小生产范围，不把所有规划都当首发门槛

首期可以限定为一个部门、一个平台服务、少量受信任的专用执行电脑和少量明确的业务流程。任务接入、双触发、入参、执行状态、日志结果、故障告警、角色权限、备份恢复属于必要能力。

在实际投产前仍需完成以下直接关系到真实业务的门槛：

1. 执行电脑使用正式、受限的独立系统身份，常驻启动和掉线恢复经过演练；现在的开发执行器不作为安全隔离环境。
2. 业务账号和接口凭据受控提供；对 nine 的上传确认、业务去重、部分成功恢复完成明确规则和授权测试。当前配置拒绝开启外部写入，不应直接去掉这个限制。
3. 用授权测试群和目标测试系统验证真实影刀触发、真实钉钉发送和 nine 上传，不能以模拟边界或离线预检替代。
4. 在实际服务器完成 HTTPS、访问权限、容量及数据保留、升级与恢复演练，并完成业务验收。此次已验证本地 Docker 构建和运行，之前的备份恢复记录继续有效，但不等同于实际服务器验收。

多级审批、复杂图形编排、资源市场、多集群调度、复杂告警升级不应仅因为“成熟平台通常有”而成为首期必做项。原架构规划作为后续能力清单保留，投产判断应围绕确定的首期流程和上述证据。

完整测试、缺陷与责任状态见 [本轮验收记录](testing/usability-redesign-report.md)。
