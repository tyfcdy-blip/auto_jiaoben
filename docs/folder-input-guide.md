# 文件夹输入与本机测试

2026-09-17。当前能力供本机合成测试和受信任程序联调；生产门槛见[简化方案](usability-simplification.md)。

第一次使用请先看[工作台极简使用说明](quick-start.md)，本文只补充目录输入的测试和边界细节。

## 日常只配置一次

1. 在“执行电脑”连接配置中填写运行环境路径，以及“允许读取的文件夹根目录”。导入连接文件并启动执行器；允许范围由电脑本地配置决定，登记在线状态不能代替真实心跳。
2. 在程序库上传 ZIP，选择 Python 或 Node.js、填写入口，输入方式选“文件夹”。发布程序；运行环境和依赖在执行电脑上准备，控制台不会自动安装。
3. 创建任务，选择该程序和固定执行电脑，填输入文件夹、批次编号及业务参数。只会提供支持目录输入的电脑。程序升级后已有任务不会自动改绑版本。

之后可以手动点运行，也可以配置定时计划或让影刀调用接口。每次新的文件交付使用新的批次编号；同一批次的网络重发保持原编号，平台去重。目录任务不需要去“文件批次”页面上传文件。

路径在**执行脚本的电脑**上解释，不在 Docker 容器或浏览器所在电脑上解释。工作台部署在 Linux Docker，执行电脑为 Windows 时，仍可传 `D:\业务下载\批次001`。因此本机目录模式不需要把这个文件夹挂载进工作台容器。

共享目录可使用 `\\文件服务器\共享名\批次001`，但运行执行器的 Windows 身份必须有实际读取权限。映射盘可能只对当前登录用户可见。当前本机测试不能证明另一台电脑或共享账号能访问。

## 本轮测试程序

当前已准备好的 Docker 测试地址：`http://127.0.0.1:18080/#/tasks`，使用已有 Docker 管理员账号，选择项目 **文件夹输入验收-9f7faf5e**。四个任务已绑定当前电脑，输入目录已填好；执行器已启动并核对在线。它当前是测试进程，未安装为开机服务。原 `6465` 是旧预览实例，这次目录验收请使用 `18080`。

测试输入位于本仓库 `runtime/folder-acceptance/docker-01/inputs`；不要换成真实业务目录。电脑重启或测试执行器退出后，在仓库根目录运行下面命令恢复本次测试连接：

```powershell
.venv/Scripts/python.exe -m agent --config runtime/folder-acceptance/docker-01/connection/agent.json
```

| 程序 | 输入与预期 |
| --- | --- |
| Python CSV 合并 | 读取根目录和子目录内两份 CSV，输出包含三行数据的 merged.csv |
| Node.js 目录统计 | 读取同一目录的四份合成文件，输出目录统计 JSON |
| 主动失败 | 退出码 7；运行失败，有日志、失败结果和平台告警 |
| 等待与超时 | 等待 30 秒，测试任务限时 3 秒；进程终止，平台记录超时失败 |

生成工具及开发说明见[示例程序](../examples/folder-jobs/README.md)。测试产物、输入目录和任务编号由 `runtime/folder-acceptance/*/acceptance.json` 记录；连接配置含秘密，只保存在本机，不分享。

进入测试项目，先运行 CSV 合并，每次手动测试换一个批次编号；在运行中心查看日志、结果，下载 merged.csv。运行主动失败和超时程序出现失败告警是预期结果。验收脚本创建的定时计划在验证后关闭，模拟上游凭据禁用，避免持续触发。

## 目录交付的边界

- 影刀先完成全部下载并关闭文件，再触发；建议每次交付放独立子目录，处理期间保持内容不变。
- 执行器直接读取原目录，递归生成文件清单；不复制、不上传、不提供冻结快照。示例程序不修改输入，真实脚本也应把输出写到平台指定 output_dir。
- 默认每次最多 1000 个文件、1000 个目录、深度 32，总大小 100 MiB；空目录、缺失目录、越界、链接及重解析点被拒绝。容量属于当前执行器配置，不能据此推断大批量生产性能。
- 业务执行超时从进程启动后计时，不包含目录扫描准备；网络共享阻塞和准备阶段的取消体验仍待专项完善。白名单是输入检查，不是恶意代码隔离沙箱。
- 定时参数的日期模板目前仅支持完整值，输入文件夹保持固定；相同程序、操作和业务批次只执行一次。每天多次独立处理需要不同批次编号，不能都用 `${scheduled_date}`。

## 首轮测试需要提供什么

本轮使用当前电脑、自动生成的目录、已有 Python 和 Node.js，不需要真实文件、业务账号或钉钉配置。

接入实际流程时再提供：固定执行电脑及可读目录、脚本运行环境、触发时间与批次编号规则。影刀在下载完成步骤后配置专用任务接口与调用凭据，示例见[事件接入](event-integration.md)。钉钉需要授权测试群及机器人连接配置，凭据通过本地配置或管理页面保存，不发到聊天。

真正上线前，还需完成执行电脑受限身份和开机常驻/断线恢复、真实共享权限及影刀/钉钉联调、实际服务器 HTTPS 与升级恢复验收。涉及向业务系统写入的程序还要完成凭据和部分成功恢复规则；当前开发版禁止外部业务写入，nine 的真实上传未因此完成。
